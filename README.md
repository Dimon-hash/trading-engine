# Trading Engine

Учебный REST-сервис для торговли через стакан лимитных заявок. Он проверяет параметры заявок, резервирует деньги и бумаги, исполняет встречные заявки и показывает котировки, счета и историю сделок.

## Запуск

Для локального запуска понадобятся JDK 21, Maven и Docker с Docker Compose.

### 1. Запусти PostgreSQL

На macOS открой Docker Desktop и дождись запуска Docker. Из корня проекта, где лежит `compose.yaml`, выполни команду и дождись статуса `Healthy`.

```bash
docker compose up -d --wait postgres
```

Контейнер запускает PostgreSQL 16 на `127.0.0.1:5433`. База называется `trading_engine`, пользователь — `trading`. Пароль берётся из `TRADING_DB_PASSWORD`, по умолчанию используется `trading`.

Если используешь отдельно запущенный PostgreSQL 15 или новее, перед запуском приложения укажи параметры своей базы в `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME` и `SPRING_DATASOURCE_PASSWORD`.

### 2. Запусти Spring Boot

**В IntelliJ IDEA.** Открой проект как Maven-проект и выбери JDK 21 в настройках **Project SDK**. Открой [TradingEngineApplication.java](src/main/java/com/example/tradingengine/TradingEngineApplication.java) и нажми зелёную стрелку рядом с методом `main`.

**В терминале.** Убедись, что `mvn -version` показывает Java 21, затем выполни из корня проекта `mvn spring-boot:run`. На macOS можно выбрать установленную JDK 21 в текущей вкладке терминала.

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
mvn spring-boot:run
```

Дождись строки `Tomcat started on port 8080` в логах. Flyway при первом запуске на пустой базе создаёт таблицы и добавляет демоданные.

### 3. Проверь, что API отвечает

В другой вкладке терминала выполни запрос к стакану.

```bash
curl -fsS 'http://localhost:8080/quotes?seccode=DEMO'
```

На свежем запуске ответ будет `{"seccode":"DEMO","bids":[],"asks":[]}`. Если видишь `Connection refused`, проверь, что приложение запустилось на `8080`. Если Spring Boot сообщает, что порт `8080` уже занят, проверь, запущен ли проект в другом окне терминала или в IntelliJ.

## Демоданные и хранение

Справочник инструментов читается из PostgreSQL. Начальные счета и позиции загружаются из базы при старте. Заявки, сделки, резервы и изменения денег и бумаг хранятся в памяти до перезапуска приложения.

Инструмент `DEMO` рассчитывается в рублях, содержит 10 бумаг в лоте и имеет шаг цены `0.05`.

| Счёт | Пользователь | Доступные деньги | Бумаги `DEMO` |
|---|---|---:|---:|
| `1` | `101` | 10 000 ₽ | 0 |
| `2` | `102` | 0 ₽ | 1 000 |

## Проверка сделки

### Через IntelliJ IDEA

1. Открой [requests.http](requests.http) в корне проекта.
2. Оставь **No Environment**. Адрес API и инструмент заданы в файле.
3. Нажми кнопку с двойной зелёной стрелкой над файлом (**Run All Requests in File**). Она отправит все восемь запросов по порядку.

В панели **Services** проверь результаты. Последние два запроса ожидают ответы `400` за неверный шаг цены и `409` за недостаток средств. При этих кодах проверки проходят.

Перед повторным прогоном перезапусти Spring Boot, чтобы восстановить демосчета и очистить стакан и историю сделок. Контейнер PostgreSQL можно оставить запущенным.

### Через curl

На свежем запуске выставь продажу одного лота со счёта `2`, затем покупку двух лотов со счёта `1`. В заявках `price` — цена за одну бумагу, `quantity` — количество лотов.

```bash
curl -sS -X POST http://localhost:8080/orders -H 'Content-Type: application/json' -d '{"accountId":2,"seccode":"DEMO","side":"SELL","price":100,"quantity":1}'
curl -sS -X POST http://localhost:8080/orders -H 'Content-Type: application/json' -d '{"accountId":1,"seccode":"DEMO","side":"BUY","price":101,"quantity":2}'
```

Один лот исполнится по цене 100 ₽ за бумагу. Покупатель получит 10 бумаг, продавец — 1 000 ₽. На следующий лот у покупателя останется резерв 1 010 ₽ и доступный баланс 7 990 ₽.

Следующие запросы покажут счета, стакан и реестры.

```bash
curl -sS http://localhost:8080/accounts/1
curl -sS http://localhost:8080/accounts/2
curl -sS 'http://localhost:8080/quotes?seccode=DEMO'
curl -sS 'http://localhost:8080/orders?seccode=DEMO'
curl -sS 'http://localhost:8080/trades?seccode=DEMO'
```

Отмени неисполненный остаток покупки. Подставь `orderId` из ответа на создание заявки. На свежем запуске в этом сценарии он равен `2`.

```bash
curl -sS -X POST 'http://localhost:8080/orders/2/cancel?seccode=DEMO'
curl -sS http://localhost:8080/accounts/1
```

Доступный баланс покупателя станет 9 000 ₽, денежный резерв — 0 ₽. Сделка останется в реестре.

## Методы API

| Метод и путь | Действие |
|---|---|
| `POST /orders` | Создать заявку с `accountId`, `seccode`, `side`, `price` и `quantity`. |
| `PATCH /orders/{id}?seccode=DEMO` | Изменить цену открытого остатка. Пример тела — `{"price":100.50}`. |
| `POST /orders/{id}/cancel?seccode=DEMO` | Снять остаток со стакана и освободить резерв. |
| `GET /orders?seccode=DEMO` | Получить заявки со статусами и открытыми остатками. |
| `GET /trades?seccode=DEMO` | Получить историю сделок. |
| `GET /quotes?seccode=DEMO` | Получить `bids` и `asks` с суммой открытых лотов по каждой цене. |
| `GET /accounts/{id}` | Получить `availableBalance`, `reservedBalance` и `positions` с остатками бумаг. |

При отсутствии счёта или инструмента создание заявки возвращает `404`. Некорректная цена, количество или отсутствующий `accountId` возвращают `400`. Недостаток денег или бумаг, несовпадение валют и попытка изменить или отменить закрытую заявку возвращают `409`.

Стакан выбирает лучшую встречную цену. При равных ценах заявки исполняются в порядке поступления. Изменение цены переводит открытый остаток в конец очереди по новой цене и может сразу привести к сделке. Денежный резерв пересчитывается только на оставшиеся лоты.

## Структура проекта

- `order.service` управляет созданием, изменением цены и отменой заявок и формирует снимки реестров по инструменту.
- `account.service` ведёт доступные деньги и бумаги, резервы и расчёты по сделкам.
- `matching` содержит стакан и алгоритм сопоставления заявок.
- `instrument` читает справочник через JDBC. Проверки вынесены в подпакеты `validation`.
